# Отчёт о проверке сайта перед запуском

Документ, который получает заказчик после проверки сайта. Отвечает на один
вопрос — можно ли запускать, — и только потом перечисляет находки.

Третья из семи новых работ для портфолио профиля FL.ru `kusaka63`.

## С чего начать

Читать `docs/superpowers/specs/2026-09-14-otchet-proverka-design.md` — там
решение целиком: предмет проверки, результаты замера, структура документа,
правила печати в PDF, устройство и что проверяется у самого отчёта.

Дальше по порядку: план работ, вёрстка, предпросмотр со скриншотом, правки,
выкладка на GitHub Pages.

## Состояние на 14.09.2026

Отчёт свёрстан, проверен и выложен:
https://pyhphhddb8-eng.github.io/otchet-proverka/

В портфолио FL.ru стоит третьей работой.

## Как повторить проверки

    python3 tools/proverka.py

Скрипт сверяет каждое число страницы с сохранёнными отчётами в `zamery/`,
считает контраст девяти цветовых пар по формуле WCAG и следит, что страница
осталась самодостаточной — без единого внешнего запроса.

Вспомогательные скрипты, в готовую страницу не попадают:

    python3 tools/shrift.py    # подрезать шрифт под текст страницы
    python3 tools/ikonka.py    # нарисовать иконку и favicon.ico
    python3 tools/preview.py   # нарисовать og.png для превью ссылки
    python3 tools/oblozhka.py  # квадратная обложка для портфолио

## Единицы измерения

Числа берутся из Lighthouse дословно, в его единицах, а слово пишется
привычное — «КБ». Поэтому вес страницы здесь 82 КБ, а не 81, как было в
первой редакции спеки: две системы счёта в одном документе ломают главное
свойство отчёта — возможность повторить замер и сойтись в цифрах.

## Предмет проверки

Собственный каталог аренды инструмента:

Свой сайт, а не выдуманный клиентский: адрес открыт, любой может повторить

## Что показал замер

Lighthouse 13.4.1, мобильный режим с замедлением сети, медиана трёх прогонов,
14.09.2026. Сырые отчёты лежат в `zamery/` — числа в документе должны
сходиться с ними.

Производительность 98, доступность 98, лучшие практики 100, SEO 63.
Вес страницы 81 КБ, главный элемент за 1,4 с, скачков вёрстки нет.

Три находки к исправлению: пропуск уровня заголовков (после `h1` сразу `h3`),
нет файла `favicon.ico` при наличии svg и apple-touch, 41 КБ неиспользуемого
JavaScript.

SEO 63 — следствие `noindex`, поставленного намеренно: это демо с условными
ценами. Кэширование на GitHub Pages вне зоны ответственности.

## Осторожно с замерами

Вес страницы меряется так, как его качает браузер — со сжатием. `curl` без
заголовка `Accept-Encoding` показывает распакованный размер: 250 КБ вместо
реальных 77 КБ для того же файла. На этой ошибке уже один раз построили
неверный вывод.

## Что делаем после

Три находки чинятся в каталоге после публикации отчёта. Тогда появится вторая
версия документа и пара «было / стало».
